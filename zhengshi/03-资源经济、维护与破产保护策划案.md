## 1. 目标和经济不变量

经济系统的目的，是让玩家在“情报、补给、现金、支援和队伍恢复”之间作出有机会成本的选择，而不是逼玩家刷低级委托。正式版首章初测基线允许正常赚钱，但必须消耗行动周期、维护和队伍状态；任何资源都不能在不推进周期、不承担风险的情况下无限增长。

### 1.1 冻结规则

- **R03-01 [冻结]** 每种资源都有明确的来源、消耗、预留、提交、退还、上限和负值处理。
- **R03-02 [冻结]** 情报是永久事实 ID 集合，不是可以反复购买和消耗的货币；同一事实 ID 只首次加入档案。
- **R03-03 [冻结]** 声望和势力态度不是通用货币，不得在一个界面中直接兑换为资金或补给而不经过具体事件。
- **R03-04 [冻结]** 所有资源增量都绑定来源 ID 和结算 `commit_id`，重复提交不重复增加。
- **R03-05 [禁止]** 任何准备动作不能同时不消耗时间、不消耗机会、不消耗资源而稳定产生正收益。
- **R03-06 [冻结]** 破产保护提供的是最低可玩路径，不是免费现金注入；援助不得让玩家可支配资产超过触发危机前的合理净价值。
- **R03-07 [冻结]** 维护、治疗、债务和助力代价均在周期结算中可追踪，不能用读档或取消界面删除已经提交的费用。
- **R03-08 [基线]** 正式版首章初测使用低规模数值，平衡结论必须来自经济模拟和试玩，不能仅凭表格宣布完成。

## 2. 资源账本模型

所有资源使用同一账本结构：

```text
LedgerEntry
  ledger_id
  resource_id
  amount
  state: committed | reserved | debt | fact
  source_id
  cycle_id
  commit_id
  refundable
  reason_key
```

玩家可见值按以下方式计算：

```text
可用值 = committed - reserved - 已到期冻结 + 可用信用额度
```

`debt` 不应偷偷混入可用现金；它必须单独显示，并通过事件或维护规则偿还。`fact` 集合使用 `fact_id` 去重，不使用加减数值。

### 2.1 资源总表

| 资源 | 类型 | 主要用途 | 能否为负 | 上限/去重 | 典型风险 |
|---|---|---|---:|---|---|
| 资金 `gold` | 可计量货币 | 采购、设施、治疗、维护、任务成本 | 默认否；破产转债务 | 软上限由仓储/信用决定 | 破产、债务、政治援助 |
| 补给 `supply` | 可计量库存 | 远征治疗、露营、工具和应急 | 否 | 携带上限/仓储上限分开 | 过量携带、回城囤积 |
| 情报 `fact_id` | 事实集合 | 揭示风险、路线、敌方机制 | 不适用 | 同一 ID 只加入一次 | 重复购买、随机硬门槛 |
| 工会声望 `reputation` | 世界状态 | 委托层级、公共信任和要求 | 允许最低值但不当货币 | 章节上限待测 | 高声望高压力 |
| 势力态度 `faction_state` | 多维状态 | 委托、政策、政治后果 | 不直接消费 | 每势力独立 | 互斥站队 |
| 联络位 `contact_slot` | 周期容量 | 准备特殊 NPC 支援 | 不允许负值 | 周期开始锁定 | 同时支援过多 |
| 债务 `debt` | 负债状态 | 破产保护和黑市周转 | 只可为正 | 债权人上限 | 主动破产套利 |

## 3. 来源、预留和提交

### 3.1 三阶段账务

1. **预览：**只显示预计变化，不写账本。
2. **预留：**在 `PREP_LOCKED` 或服务确认时，把可退费用转为 `reserved`。
3. **提交：**结果或周期事务成功时，将 `reserved` 转为最终消耗，并写入来源和日志。

取消规则：

- 出发锁定失败：全部可退预留释放。
- 玩家在允许取消窗口取消：可退预留释放，不退已明确标记为不可退的服务成本。
- 出发后：预留不能因为返回菜单或读取同 epoch 快照以外的页面而释放；由任务结果结算。
- 结算后：只有新事件可补偿，不允许直接改历史账本。

### 3.2 费用分类

| 费用 | 预留时机 | 最终提交时机 | 失败是否退还 |
|---|---|---|---|
| 购买情报 | 购买确认 | 事实确认并写入档案 | 否；重复事实不收费 |
| 携带补给 | 出发锁定 | 实际消耗按结果提交 | 未消耗部分按规则带回 |
| 远征基础成本 | 出发锁定 | 出发成功即提交 | 否 |
| 地图工具 | 使用确认 | 节点/战棋结果提交 | 不因重试退回；战斗内临时效果由战斗快照处理 |
| 特殊 NPC 支援 | 支援调用合法且效果启动 | 支援效果事务提交 | 调用失败按支援卡定义，不能 UI 取消 |
| 治疗服务 | 服务确认 | 服务完成或周期关闭 | 已完成服务不退 |
| 周期维护 | 周期关闭 | 关闭事务 | 不退；破产转债务/压力 |

## 4. 正式版首章初测基线

以下是用于灰盒经济模拟的起始值，不代表正式版最终平衡：

| 项目 | 基线 | 备注 |
|---|---:|---|
| 初始资金 | 120 | 货币单位，可用值不能低于 0 |
| 初始补给 | 6 | 仓储上限建议 10 |
| 初始情报 | 0 个事实 ID | 通过准备委托或调查获得 |
| 初始工会声望 | 0 | 只通过事件改变 |
| 每周期基础维护 | 20 | 资金不足进入破产压力，不直接结束 |
| 普通出战人数 | 3 | 4 名初始成员中选择，主角为领队 |
| 支援联络位 | 1 | 同周期最多准备一个高影响支援 |
| 基础治疗 | 10 资金/名轻伤 | 具体效果由 `07` 定义 |
| 基础补给采购 | 10 资金/份 | 不得在周期内无限采购而不结束周期 |
| 最低恢复服务 | 0 即时现金 | 产生债务/声望/时间代价，不发可自由转卖现金 |

所有基线须通过至少 20 周期的模拟，并测试高收入、低收入、连续失败和主动消耗四种轨迹。

## 5. 收入与重复委托

常规委托可以提供稳定收入，这是经营的正常成长，不应简单地被设计为不能重复。但它必须同时受到以下约束：

- 每个任务实例在一个周期内只能完成一次。
- 同一委托族的刷新需要周期关闭，不允许在 `PREPARING` 反复刷新。
- 任务消耗出战机会、补给、维护或队伍状态。
- 委托收益应按风险和时间计算，不允许风险为零且净收益无限高。
- 高声望增加要求、维护和政治关注，不能只增加收入。
- 重复委托奖励只在内容配置声明 `repeatable = true` 时存在；一次性证据、特殊道具和支线奖励永不按常规委托刷新。

### 5.1 净收益审计

每类任务记录：

```text
净资金 = 任务收入 - 出发成本 - 预期维护分摊 - 治疗期望值 - 必要采购
净补给 = 任务补给收益 - 预计消耗
周期机会成本 = 占用的周期/联络位/核心队伍状态
```

安全任务可以净资金为正，但若它让玩家完全不承担周期机会成本或状态成本，则判定为经济漏洞。

## 6. 维护、上限和溢出

### 6.1 维护顺序

周期关闭时按以下顺序处理：

1. 汇总本周期已提交任务和服务。
2. 结算应收资金、未领取但合法的固定收益。
3. 结算设施和基础成员维护。
4. 结算欠费、债务和势力承诺。
5. 结算留守恢复和可用的治疗。
6. 检查破产、危机、声望门槛和世界事件。
7. 生成下周期可见摘要。

维护不能在玩家阅读页面或查看仓库时偷偷发生。

### 6.2 上限处理

- 补给超过仓储上限时，默认不允许完成采购；若内容允许丢弃，必须由玩家确认，不能静默丢失。
- 情报重复获得不增加数值；应转化为可信度提高、替代线索或小额一次性反馈，但不能反复刷钱。
- 声望超过章节软上限时，溢出转化为更高要求、政治关注或等待下一章节，不转成资金。
- 联络位超过容量时，不能自动替换已经锁定的 NPC；玩家必须在准备阶段主动取消或选择。

## 7. 破产状态与最低可玩路径

### 7.1 进入条件

在周期维护或明确的资金结算后，如果：

```text
可用资金 < 0 或 资金无法支付必须维护且未获准延期
```

进入 `FINANCIAL_PRESSURE`。若债务超过债权人/设施允许上限，进入 `RESTRUCTURE_PENDING`，但不立即结束游戏。

### 7.2 可选恢复方案

| 方案 | 立即效果 | 代价 | 可否重复 |
|---|---|---|---:|
| 最低桌面恢复服务 | 允许查看恢复委托、处理全员重伤的基础医疗 | 增加债务或降低民众声望；占用本周期 | 可用，但债务有上限 |
| 基础恢复委托 | 提供少量物资/资金或减债 | 不要求健康出战者；完成后推进周期 | 每个危机阶段一次 |
| 势力援助 | 暂时解决一项维护/物资问题 | 政治承诺、未来委托义务、另一势力不满 | 每势力章节限一次 |
| 出售非关键资产 | 获得现金 | 永久失去资产或降低设施能力 | 每项资产一次 |
| 黑市周转 | 避免当前维护失败 | 债务、合法性和后续追责 | NPC/章节限制 |

最低桌面恢复服务不是 0 成本：它不需要现金、健康角色或特殊 NPC，但会增加可见债务、消耗一个周期机会或降低一个公共状态；它只保证“仍能做下一步”，不保证回到正常经营。

### 7.3 防止主动破产套利

触发破产保护后：

- 不发可自由转卖的现金包。
- 援助的总可支配价值不得高于触发危机前一周期玩家能够通过正常低风险行动得到的净价值。
- 债务、声望或政治承诺必须在同一结算摘要中显示。
- 重复援助不能刷新所有资源；同一危机使用过的恢复方案有 `recovery_claim_key`。
- 若玩家主动把资金降至零，恢复服务仍可用，但恢复后的可执行路径受债务和周期机会限制，不形成正收益循环。

### 7.4 绝境状态

若资金为 0、补给为 0、所有成员重伤或不可出战，系统仍必须提供：

1. 打开最低桌面恢复服务。
2. 生成不要求战斗出场的恢复/调查/谈判委托。
3. 允许使用非现金代价完成一次恢复。
4. 在结果后让至少一名成员进入可出战或可承担岗位状态。

不可接受的设计是“所有人不能战斗 → 只能接必须战斗的任务 → 无法继续”。

## 8. 经济平衡模拟

在实现内容前建立离线表格或脚本，模拟至少以下轨迹：

| 轨迹 | 初始情况 | 目标 |
|---|---|---|
| 正常成长 | 选择中等风险任务，偶尔治疗 | 资源缓慢增长，不出现指数爆发 |
| 极端节省 | 不买情报、不用支援 | 主线可通行，但风险和成本更高 |
| 高支出 | 频繁支援、提前治疗 | 不因一次支出立即软锁，有恢复路径 |
| 连续失败 | 两次失败或撤退 | 债务/声望/世界后果增加，但可继续 |
| 主动破产 | 故意耗尽资金 | 恢复价值不高于正常经营，不能套利 |
| 反复安全任务 | 连续五个周期做低风险任务 | 收益受维护、状态和内容机会约束 |

每次模拟记录：周期、资金、补给、债务、声望、队伍可用度、支援次数、任务进度和世界压力。未完成模拟前，不得将任何“经济稳定”写入验收结论。

## 9. 验收用例

| ID | 场景 | 预期 |
|---|---|---|
| TC03-01 | 购买同一情报事实两次 | 第二次不收重复货币，不重复奖励 |
| TC03-02 | 预留费用后取消出发 | 可退费用完整释放，取消日志存在 |
| TC03-03 | 出发后撤退 | 基础远征成本和已用补给按规则提交，不返还已提交部分 |
| TC03-04 | 连续五次安全委托 | 每次都推进周期并产生维护/机会成本，不出现无时间刷钱 |
| TC03-05 | 资金归零、补给归零、全员重伤 | 能进入最低恢复服务并生成可继续委托 |
| TC03-06 | 主动花光资金再申请援助 | 不获得可自由转卖的净正收益，债务/声望代价可见 |
| TC03-07 | 维护扣费失败 | 进入压力状态，不丢失任务状态，不半扣费 |
| TC03-08 | 补给超过上限 | 采购被拒或由玩家确认丢弃，不静默溢出 |
| TC03-09 | 同一恢复援助重复请求 | `recovery_claim_key` 阻止重复获得 |
| TC03-10 | 读取旧档后结算另一条路线 | 新旧时间线整包分离，不合并资金和奖励 |

## 10. 实施任务

1. 建立统一账本接口和来源/提交/退还状态。
2. 把情报改为 `fact_id` 去重集合，移除“情报货币化”歧义。
3. 为任务、维护、援助和恢复服务建立稳定 claim key。
4. 配置首章基线并运行六类经济轨迹模拟。
5. 实现破产压力、最低桌面恢复和重整状态。
6. 在 UI 显示可用、预留、债务、周期机会成本和预计结果。
7. 完成 TC03-01 至 TC03-10 后，才能冻结 DEMO 数值。
