# 04 行动周期、任务生命周期与世界推进策划案

## 1. 目标和不变量

本文件把“什么时候算过了一段时间”写死，防止玩家在准备界面无限刷资源，也防止玩家因阅读日志或普通菜单操作被暗中惩罚。

### 1.1 冻结规则

- **R04-01 [冻结]** 世界周期只在 `CYCLE_CLOSED` 关闭事务中递增一次；所有推进必须绑定 `cycle_id`。
- **R04-02 [冻结]** `PREPARING` 中查看日志、检查队伍、阅读情报、浏览委托和打开角色档案不消耗周期、不消耗资源。
- **R04-03 [冻结]** 只有明确标记为周期动作的经营、休整、出发、任务或恢复操作，才会在关闭周期时触发维护和世界推进。
- **R04-04 [冻结]** 远征中的移动、营地和战棋回合增加 `local_tick`，不直接增加世界周期；远征结束后由结算决定是否关闭周期。
- **R04-05 [冻结]** 委托期限使用显式周期或阶段单位；完成结果先结算，再判定本周期结束时的期限后果。
- **R04-06 [冻结]** 主线没有隐藏的持续倒计时；若章节引入临界事件，必须在界面预告“本周期不处理会发生什么”。
- **R04-07 [冻结]** 政策切换不能刷新任务实例、抹去承诺或重置已领取奖励；已接受任务绑定接受/锁定时的政策版本。
- **R04-08 [禁止]** 通过反复退出进入、取消对话或重开菜单刷新任务列表、随机种子或商店库存。

## 2. 时间单位

| 单位 | 说明 | 是否推进世界周期 |
|---|---|---:|
| 菜单时间 | 浏览、阅读、查看因果和配置界面 | 否 |
| 准备动作 `prep_action` | 本周期有限的高价值经营选择 | 否，动作数耗尽后仍需关闭周期 |
| 远征 `local_tick` | 移动、节点调查、营地、战棋回合 | 否，记录局内压力 |
| 行动周期 `cycle_id` | 筹备、远征/休整、结算、回响、维护 | 是，关闭时 +1 |
| 章节节拍 | 多个周期或重大任务完成后的世界节点 | 由明确条件触发 |

### 2.1 准备动作基线

正式版首章初测使用每周期 `prep_actions = 2` 的建议基线：

- 查看信息和进入普通界面不占用动作。
- 购买一组情报、训练/治疗一次、联系一名 NPC、接受一项准备委托等可标记为一个准备动作。
- 每个动作必须有结果、机会成本或可见的资源变化；不能只是点击确认。
- 动作数耗尽后仍可查看和撤销未锁定的配置，但不能继续执行同类收益动作。
- 出发、休整或完成恢复委托时关闭周期并重置下一周期动作数。

DEMO 可以把动作数缩减为 1–2，但必须保留至少一次“资源与信息之间的取舍”。

## 3. 行动周期流程

```text
CYCLE_CREATED
  -> PREPARING
  -> PREP_LOCKED       出发配置锁定
  -> EXPEDITION        远征
  -> RESULT_PENDING    产生结果
  -> SETTLED           接受并提交结果
  -> ECHO              处理队伍短回响和 NPC 通知
  -> CYCLE_CLOSED     维护、期限、世界推进、恢复
  -> CYCLE_CREATED + 1
```

若玩家不出发，可以在准备阶段选择：

- **休整周期：**支付维护，进行留守恢复，推进等待中的世界事件。
- **经营周期：**执行规定的少量经营动作后关闭周期。
- **恢复周期：**处理破产、伤病或补救委托，结果同样进入结算和关闭。

“返回工会”只是远征内的结果出口，不自动开始无限新的周期；玩家必须接受结果并完成关闭事务。

### 3.1 关闭事务顺序

1. 结算本周期最后一个结果。
2. 处理回响队列中已经触发的短内容。
3. 结算维护、债务、恢复和设施状态。
4. 判定任务期限和世界事件状态。
5. 推进 NPC 支线中标记为“周期后推进”的阶段。
6. 更新委托板、商店、可见线索和准备动作。
7. 写入 `CYCLE_CLOSED` 自动存档。
8. 创建下一个 `cycle_id` 和 `PREPARING` 快照。

同一关闭请求重复发送时，通过 `cycle_close_commit_id` 幂等，不重复维护、恢复或推进事件。

## 4. 任务生命周期

任务实例使用稳定 `quest_instance_id`，状态为：

```text
VISIBLE
ACCEPTED
PREPARING
DISPATCHED
IN_PROGRESS
COMPLETED
COST_SUCCESS
PARTIAL_SUCCESS
WITHDRAWN
FAILED_CONTINUES
CONVERTED
EXPIRED
CLOSED
```

### 4.1 状态说明

| 状态 | 进入条件 | 可执行动作 | 退出条件 |
|---|---|---|---|
| `VISIBLE` | 委托刷新/事件产生 | 查看、比较、拒绝 | 接受、过期、转化 |
| `ACCEPTED` | 玩家确认接单 | 配置和准备 | 出发、取消、期限变化 |
| `PREPARING` | 已接单未锁定 | 执行有限筹备 | 锁定、取消、过期 |
| `DISPATCHED` | 出发锁定成功 | 远征局内行动 | 结果待结算、撤退 |
| `IN_PROGRESS` | 已到达目标区域 | 调查、战斗、交涉 | 多级结果 |
| `COMPLETED` | 主要目标完成 | 查看结算 | 关闭 |
| `COST_SUCCESS` | 目标完成但有代价 | 查看代价/后续 | 关闭或后续任务 |
| `PARTIAL_SUCCESS` | 部分目标完成 | 接受后续补救 | 关闭或转化 |
| `WITHDRAWN` | 玩家合法撤退 | 查看局势后果 | 关闭或补救 |
| `FAILED_CONTINUES` | 核心目标失去 | 接受追责/救援/补救 | 关闭或补救 |
| `CONVERTED` | 期限/选择将其转为新事件 | 处理新事件 | 关闭或新任务 |
| `EXPIRED` | 显性期限满足且未完成 | 查看后果 | 转化/关闭 |
| `CLOSED` | 结果和后果已提交 | 只读日志 | 不可重新打开 |

### 4.2 并发和刷新

- 任务板每个周期关闭时刷新一次，不在准备菜单反复刷新。
- 主线任务最多一个活动实例；支线、准备委托和危机委托的并发上限由章节配置。
- 同一委托族可以重复，但同一 `quest_instance_id` 不能重复完成。
- 玩家拒绝普通委托不消耗周期；接受后取消可有明确的声望、信誉或机会代价，不能无成本重复试探隐藏信息。
- 任务实例中途退出不回到 `VISIBLE`，必须进入取消、撤退、失败或转化状态。

## 5. 期限与临界事件

### 5.1 期限表达

期限必须在委托界面显示：

```text
deadline_kind: cycle / chapter_beat / local_tick
deadline_value:
warning_at:
consequence_preview:
```

建议：

- `cycle` 用“本周期/下周期结束前”表达。
- `chapter_beat` 用“下一章节节点前”表达。
- `local_tick` 只用于远征内部压力，不直接让玩家失去尚未查看的主线。

### 5.2 期限判定顺序

本周期完成任务的结果先写入 `RESULT_PENDING` 并结算；之后在 `CYCLE_CLOSED`：

1. 判断任务是否已完成或转化。
2. 对仍未完成且达到 `deadline_value` 的任务执行过期后果。
3. 写入新的危机/追责/敌方推进任务，不简单删除内容。
4. 推进等待中、发展中、临界事件。
5. 提示下周期的新风险。

这样玩家在期限边界完成任务时不会因结算顺序不透明而被偷判失败。

### 5.3 主线压力

主线可以有明确的章节压力和事件推进，但不使用玩家无法观察的持续倒计时。若某周期不处理会：

- 提高敌方警戒。
- 改变一个节点状态。
- 关闭一个可选目标。
- 生成追责/救援/谈判后续。

必须在任务日志里列出至少一种后果类别和下次检查点。

## 6. 政策锁定与切换

### 6.1 政策状态

```text
policy_id
policy_revision
active_since_cycle
next_change_available_cycle
bound_quest_instances[]
political_cost_preview
```

政策只能在以下时机修改：

- 章节节点明确允许时；或
- 连续完成 3 个周期后，在准备阶段执行一次制度调整。

正式版后续可以测试其他频率，但不能允许玩家在同一任务看到结果后随意切换。

### 6.2 绑定规则

- 已接受任务记录接受时的政策版本；出发锁定后使用锁定快照中的政策。
- 政策切换不取消已形成的债务、承诺、声望和势力变化。
- 政策切换会产生明确成本：时间机会、资金、民众声望、势力不满或下一周期任务结构变化，至少一种必须发生。
- 政策不能同时激活互斥路线的全部收益；若内容允许短期妥协，必须产生第三方或长期后果。
- 读取旧档是回到旧时间线，不视为在当前时间线免费切换政策。

## 7. 特殊 NPC 支线生命周期

特殊 NPC 支线阶段至少记录：

```text
npc_quest_id
stage_id
stage_state: available / active / delayed / warning / resolved / missed / converted
earliest_cycle
warning_cycle
deadline_cycle
missed_result
next_assist_unlock
```

### 7.1 延后规则

- 没有期限的支线可延后，不暗中降低好感或永久消失。
- 有期限的支线在进入 `warning` 前至少显示一次“不处理的后果类别”。
- 支线错过后进入理解得通的 `missed` 或 `converted` 结果，例如 NPC 改变工作地点、助力变为更高成本服务、生成补救任务。
- 支线不会因为玩家拒绝一次帮助而无理由消失；除非该角色的个人处境明确要求离开，并在触发前预告。
- 同一周期推进的深度支线数量建议不超过 1 条，避免回城弹窗拥堵。

### 7.2 支线互斥

若两条支线争夺同一地点、资源或势力支持：

- 在玩家确认不可逆选择前，显示会关闭的方向类别。
- 未选择的一方转为延后、降级或新任务，不直接删除整条内容。
- 互斥结果必须进入日志，说明不是随机丢失。

## 8. 经营和准备动作分类

| 类型 | 示例 | 是否推进周期 | 是否可重复 |
|---|---|---:|---:|
| 查看动作 | 日志、档案、地图、委托对比 | 否 | 是 |
| 资源动作 | 采购、治疗、制作一次工具 | 消耗准备动作；周期关闭才维护 | 受动作数/库存限制 |
| 信息动作 | 购买事实、分析线索、咨询 NPC | 消耗准备动作或独立支援次数 | 同一事实不重复购买 |
| 任务动作 | 接受/取消/推进准备委托 | 接受不立即推进；完成任务后关闭周期 | 任务实例一次 |
| 队伍动作 | 组队、分配留守岗位、训练 | 消耗准备动作或固定成本 | 受状态和岗位限制 |
| 周期动作 | 出发、休整、恢复、经营周期 | 是 | 每周期一次 |

取消或重复进入界面不会刷新商店、任务、随机种子和支援可用状态。

## 9. 远征返回和周期关闭边界

- 远征成功返回后必须先进入 `RESULT_PENDING`，玩家接受结果后才进入 `SETTLED`。
- 撤退不是直接回到准备界面；它生成撤退结果、提交已发生消耗和世界后果。
- 露营不会自动跳过世界周期，但会增加 local tick、消耗补给并可能触发远征内风险。
- 玩家选择回城休整时，周期关闭事务仍会结算维护、恢复和世界推进。
- 远征中断只能通过明确撤退、战棋撤离、失败结果或崩溃恢复退出，不能通过菜单“取消任务”抹除远征已发生的变化。

## 10. 规则验收用例

| ID | 场景 | 预期 |
|---|---|---|
| TC04-01 | 反复打开任务板 | 不刷新实例、不改变随机种子、不消耗周期 |
| TC04-02 | 连续执行两次准备动作 | 第三次被限制；必须通过周期关闭刷新 |
| TC04-03 | 读取日志和角色档案 | 不推进 deadline、不产生维护 |
| TC04-04 | 本周期最后一天完成任务 | 先结算完成，再判定剩余任务期限 |
| TC04-05 | 不出发选择休整 | 结算维护、留守恢复和事件推进一次 |
| TC04-06 | 远征移动十次 | 只增加 local tick，不增加 world cycle |
| TC04-07 | 任务接受后切换政策 | 已接受任务仍使用绑定政策版本，旧承诺不消失 |
| TC04-08 | 连续切换政策 | 未到允许周期或未支付成本时拒绝 |
| TC04-09 | 延后无期限 NPC 支线 | 阶段保留，不能暗降或随机消失 |
| TC04-10 | 期限任务未处理 | 生成预告过的转化/追责事件，不无声删除 |
| TC04-11 | 重复关闭同一周期 | `cycle_close_commit_id` 保证只维护一次 |
| TC04-12 | 远征撤退 | 进入结果结算，提交已发生消耗和可见后果 |

## 11. 实施任务

1. 建立 `cycle_id`、`local_tick` 和周期关闭事务。
2. 实现任务实例状态机、并发上限和周期刷新点。
3. 将期限检查放进周期关闭事务，禁止内容脚本自行判定过期。
4. 建立政策版本、任务绑定和切换冷却。
5. 建立 NPC 支线阶段、预告和转化结果字段。
6. 实现准备动作额度及预留/取消/提交逻辑。
7. 完成 TC04-01 至 TC04-12，并与 `03` 的经济模拟联动。
