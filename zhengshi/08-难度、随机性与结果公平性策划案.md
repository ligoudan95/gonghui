## 1. 设计目标

随机性应制造局面变化，不应突然抹掉长期经营；难度应改变容错和敌方决策，不应让玩家用读档和改档获得不对称奖励；重试应允许学习战术，但不能回滚战前已经发生的地图和经济后果。

### 1.1 冻结规则

- **R08-01 [冻结]** 远征在出发锁定时生成 `expedition_seed`；同一远征重试不更换根种子。
- **R08-02 [冻结]** 随机流按用途分离：战棋行动、次要事件、表现/动画不得共享一个无法审计的全局随机游标。
- **R08-03 [冻结]** 读取日志、跳过动画、打开菜单和结算预览不得消耗随机数。
- **R08-04 [冻结]** 主线关键事实、主线基础通行和关键结果出口不能依赖一次随机判定成功。
- **R08-05 [冻结]** 难度在 `PREP_LOCKED` 时锁定；未出发前可改，进入下一周期可改；战棋中不能改。
- **R08-06 [冻结]** 默认、低、挑战三档可以改变容错、敌方决策、信息提示和伤病后果；同一任务的基础报酬不因难度改变。
- **R08-07 [冻结]** 可及性与帮助设置可以在任意合法时机调整，但不得重置战斗、任务结果、随机种子或奖励。
- **R08-08 [冻结]** 免费战棋重试恢复完整战斗开始快照和战斗随机流游标；战前地图助力、采购和已获得事实不恢复。
- **R08-09 [禁止]** 不能用“低难度奖励降低”作为阻止可及性或低难度正常游玩的替代方案。
- **R08-10 [基线]** 正式版高风险永久死亡模式未冻结，DEMO 不依赖该模式。

## 2. 随机种子与随机流

### 2.1 种子结构

```text
expedition_seed
  combat_stream_seed
  node_stream_seed
  minor_reward_stream_seed
  ai_tiebreak_stream_seed
  presentation_stream_seed
```

`expedition_seed` 在出发锁定时写入远征快照；同一次远征所有合法重试沿用该种子和相应流的战斗开始游标。

### 2.2 随机流规则

| 随机流 | 可影响 | 不可影响 |
|---|---|---|
| `combat_stream` | 次要命中偏差、敌方非关键选择、非关键掉落 | 主线目标、撤退出口、必需事实 |
| `node_stream` | 环境小变化、非关键遭遇 | 唯一主线线索、唯一通行方式 |
| `minor_reward_stream` | 小额资源或可选奖励 | 核心任务奖励、唯一证据 |
| `ai_tiebreak_stream` | 多个同优先级 AI 行为排序 | 已明确目标的硬性行动 |
| `presentation_stream` | 表现变体、台词顺序 | 任何游戏状态 |

随机调用必须记录 `stream_id`、调用标签和游标。调用失败或事务回滚时，游标按事务快照回滚；菜单和 UI 不调用随机接口。

### 2.3 读档和重试

- 战棋重试读取 `CombatRetrySnapshot` 的流游标，不能因为重试次数增加而重新抽取战前地图风险。
- 读旧手动档是切换时间线，加载档中的种子和游标，不与当前档合并。
- 同一种子相同战术可以复现相同结果；不同战术允许改变行动顺序、目标和资源消耗，从而产生不同结果。
- 不要求玩家通过改变 UI 点击顺序来“撞出好骰子”；若需要不同结果，应来自真实战术或明确行动选择。

## 3. 风险区间模型

任务界面可以显示“低/中/高”或区间，而不是虚假的精确百分比。内部仍需保留可解释的因素分解：

```text
risk_score = base_risk
           + route_risk
           + enemy_pressure
           + party_state_modifier
           - information_modifier
           - preparation_modifier
           + bounded_random_modifier
```

建议因素优先级：

1. 目标和环境的固定风险。
2. 队伍适配、伤病、疲劳、压力和士气。
3. 已知信息、路线、补给和工具。
4. 特殊支援及其限制。
5. 有界的次要随机扰动。

### 3.1 结果解释

结算至少显示前三个主导因素和一条可改进方向，例如：

```text
结果：部分成功
主要原因：
- 已识别塌方风险，避免了最坏路线（降低环境风险）
- 队伍中一名成员疲劳达到高位（降低协作）
- 未携带固定工具，证据提取耗时增加（目标代价）
下一次可尝试：安排休整、携带工坊工具或选择长路线。
```

不得只显示“随机失败”。如果结果确实受到随机扰动，日志说明该扰动属于哪个风险区间，并指向玩家可以改变的准备因素。

### 3.2 关键目标保底

- 主线必要事实至少有固定来源或多来源冗余。
- 主线通行至少有基础边，不由一次随机成功生成。
- 关键战棋撤退点不得在没有预告的随机事件中永久消失。
- 证人、主线目标等关键单位不得因一次普通随机伤害直接消失，除非玩家已确认高风险选择并看到后果类别。
- 次要奖励可以随机，但不能成为主线继续的唯一资源。

## 4. 难度预设

| 维度 | 辅助 | 标准 | 挑战 |
|---|---|---|---|
| 信息提示 | 更充分显示风险因素和目标进度 | 显示主要因素和不确定项 | 保留必要提示，隐藏次要细节 |
| 敌方决策 | 目标明确、少追击 | 标准优先级 | 更主动利用地形和增援 |
| 战斗容错 | 失败后伤病/压力较轻 | 基线后果 | 伤病、资源和世界后果更重 |
| 随机幅度 | 次要随机更窄 | 基线 | 次要随机更宽但不影响主线保底 |
| 失败恢复 | 提供更清晰的恢复建议 | 标准恢复 | 后果更长，但仍有可继续路径 |
| 基础报酬 | 与标准相同 | 与辅助相同 | 与辅助相同 |

“辅助”不是低收益模式；它的目的为信息和容错可及性，正常奖励不视为漏洞。挑战模式也不能删除基础解法或制造无法解释的主线硬卡。

### 4.1 难度锁定

- 接受任务前、任务接受后但未出发时，可以调整难度。
- `PREP_LOCKED` 成功后锁定本次远征难度。
- 战棋、结果预览和结算中禁止切换难度。
- 下一周期重新进入 `PREPARING` 后可调整。
- 可及性、字体、速度、辅助高亮等不改变状态的设置可以随时调整。
- 调整帮助设置不得清空战斗快照、重置随机流或刷新奖励。

## 5. 坏运气保护

坏运气保护只作用于次要、可解释且不影响存档幂等的字段。建议基线：

- 连续两次相同次要资源未掉落时，下一次同类次要奖励进入保底区间。
- 连续两次遭遇非关键负面事件时，第三次只允许轻度或中性结果。
- 主要目标、关键证据和主线出口不使用“连续失败保护”来临时重写剧情，而是从一开始就保证非随机基础路径。
- 保底计数属于当前 `expedition_id` 或明确周期，不跨旧档/新档合并；战棋重试恢复战斗开始时的计数，避免通过重试累积保底。
- 保底触发和重置写入日志，玩家可查看其影响类别，但不需要看到精确概率。

如果测试发现玩家必须依赖保底才能完成主线，应先修复主线基础解法，而不是提高保底强度。

## 6. 结果与奖励公平性

### 6.1 奖励不随难度偷改

同一任务、同一完成目标在不同难度下：

- 基础报酬、主线信息、唯一结局资格相同。
- 难度只改变过程中的风险、信息量、容错和恢复压力。
- 若挑战模式有额外挑战奖励，必须是明确的可选附加内容，不能扣除其他模式的基础奖励。
- 任务接受后切难度不会重新计算已锁定的奖励表。

### 6.2 失败结果公平

失败后可以失去：

- 未完成目标对应的奖励。
- 未成功带回的物理证据。
- 补给、时间、伤病和势力空间。

失败后不能无解释地失去：

- 已获得的固定事实。
- 已提交的支援使用记录或相应反馈。
- 已结算的任务奖励。
- 继续游戏的最低恢复入口。

### 6.3 选择与随机的区分

玩家应该能回答：

- 我是因为选择了危险路线而承担风险，还是因为没有信息？
- 我是因为队伍疲劳而失败，还是因为一次无法预测的掷骰？
- 我可以通过下一次准备改变哪个因素？

若试玩中多数玩家把失败归因于“游戏随机坑我”，必须降低随机幅度、补充信息或改写目标，不用文案掩盖。

## 7. 高风险模式（待定）

正式版可以讨论永久死亡、长期伤痕增强或更严厉的任务锁定，但当前不冻结具体方案。高风险模式若进入制作，必须独立定义：

- 是否使用独立存档或模式标记。
- 难度切换是否关闭。
- 是否允许战棋重试。
- 永久损失前的确认和信息提示。
- 失败后最低可玩路径是否仍存在。
- 与默认模式的成就、奖励和结局是否隔离。

DEMO 不使用高风险永久死亡，也不应以默认模式测试结果推断该模式已经平衡。

## 8. 实例

实例 A：玩家未买情报，选择危险捷径；风险区间升高，但仍存在撤退点和长路线基础出口。失败后显示“路线和补给是主导因素”，而不是“随机失败”。

实例 B：玩家在战棋前切换到辅助难度；锁定成功后战斗使用辅助参数。奖励与标准相同；战棋中不能再改成挑战以刷成就或重置随机。

实例 C：玩家在战棋中连续重试。每次都恢复战斗开始的敌我状态和流游标；第一次尝试的临时掉落、状态和支援调用不保留。

实例 D：玩家打开日志、跳过战斗动画，再读取结果。表现流不消耗随机；同一结果仍使用同一 `result_id`，不能因 UI 操作得到不同奖励。

实例 E：次要材料连续两次未掉落，第三次触发轻度保底；主线证据和撤退点不依赖该保底。

| ID | 场景 | 预期 |
|---|---|---|
| TC08-01 | 出发时记录种子，重复读取同一战斗快照 | 关键随机状态可复现 |

| TC08-05 | 战棋中切难度 | 被拒；帮助设置仍可调整且不重置 |

## 10. 实施任务

1. 定义远征根种子、用途随机流和游标持久化字段。
2. 将主线事实、通行和撤退点从随机奖励中剥离。
3. 实现难度预设、锁定点、基础奖励相同和可及性设置隔离。
4. 实现结果因素记录和结算原因文案。
5. 配置次要奖励保底并验证不跨重试/旧档累积。
6. 完成 TC08-01 至 TC08-12，并纳入 `09` 的回归矩阵。
7. 高风险模式单独立项；在未完成独立策划前不得进入默认或 DEMO。
