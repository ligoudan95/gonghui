# 《未定名：冒险者工会》05-特殊NPC支援、联络位与基础解法策划案

> 文档版本：R1.0；状态：正式版规则基线，数值仍需原型实测。
> 适用范围：特殊 NPC、支援联络位、主线基础解法、支援失败与回城补救。
> 依赖：00 索引以及已批准的状态、结算、资源和行动周期约定；不替代 01–04 的总规则。
> DEMO 只作为实现映射参考，具体 8 节点、单位和数值由主代理在 DEMO 文档中决定。

## 1. 设计目标与冻结边界

R05-01：特殊 NPC 是可选的外部能力来源，不是主线开始、通行或完成的唯一门票。
R05-02：支援改变问题结构、信息质量或代价，不替玩家自动完成主要目标。
R05-03：每个主线关键闸门至少有一条不依赖 NPC、不依赖推荐职业的基础路线。
R05-04：资金、补给、carry、声望和政治代价必须在调用时可读；不能用隐藏好感或隐性库存扣除。
R05-05：普通冒险者不进入主角好感、恋爱或个人支援次数系统；其价值来自职业、状态和队伍构筑。
R05-06：友情、合作、恋爱三类特殊 NPC 路线拥有同等玩法强度，不共享一个全局好感上限。
R05-07：数值标签为 [基线] 或 [待定] 时只指导原型，不宣称已经实现或测试通过。

本案的成功标准是玩家能说明“为什么要联络某人、什么时候使用、付出什么、没有他还能怎么做”。
任何只增加奖励而未写入成本、时机、失败窗口、替代路线和存档幂等的支援，不得进入制作。

## 2. 统一状态与初测账本

全局事务顺序固定为 `PREPARING -> PREP_LOCKED -> EXPEDITION(NODE/COMBAT) -> RESULT_PENDING -> SETTLED -> ECHO -> CYCLE_CLOSED`。
R05-08：只有 `CYCLE_CLOSED` 的完成事务可以把 `world_cycle` 加一；移动和营地只增加 `local_tick`。
R05-09：支援不得绕过状态机；处于禁止阶段的请求必须返回原因码且不产生任何账本变化。
R05-10：`default3` 采用四名初始成员、默认三人出战的编制语义；“三”不是职业门票。
R05-11：正式版初测账本基线为资金 120、补给 6、carry 10、声望 0、维护费 20/周期。
R05-12：数值可在实测后调整，但变更必须保留前后值、影响的测试和基础解法审计。
R05-13：情报是单调累积的 `fact_id` 集合，不是可花费货币；不能显示“情报余额”并扣减事实。

|字段|基线/含义|支援系统约束|
|---|---|---|
|funds|正式版初测 120，数值待实测|费用必须在合法调用事务内扣除|
|supply|正式版初测 6，数值待实测|携带、地图与医疗消耗分开记账|
|carry_capacity|正式版初测 10，数值待实测|物理工具、药品、证据占用容量|
|prestige|正式版初测 0，数值待实测|可作为代价或结果，但不替代 NPC 次数|
|maintenance|20/周期基线，数值待实测|只在周期关闭结算一次|
|facts|`fact_id` 集合|事实不因读取、撤退或支援调用而消失|

## 3. 支援对象与状态契约

每项支援使用稳定的 `support_id`，每名 NPC 使用稳定的 `npc_id`；两者不能由显示名充当主键。
R05-14：状态集合固定为 `locked / available / reserved / used / cooldown`，不能用一个“已解锁”布尔值替代。
`locked` 表示解锁条件未满足或当前路线明确不可用；`available` 表示可在合法阶段被预留。
`reserved` 表示本次远征已选择但尚未实际调用；它冻结选择，不代表已扣费或已消耗次数。
`used` 表示一次性效果已原子提交并且没有可恢复次数；`cooldown` 表示已提交但须等条件恢复。

|字段|类型|写入时机|禁止解释|
|---|---|---|---|
|support_id|稳定字符串|内容配置创建时|不能因版本换名而变成新奖励|
|npc_id|稳定字符串|NPC 创建时|不与普通冒险者 ID 共用|
|state|五态枚举|状态迁移事务|不能以 UI 灯色替代存档值|
|uses_remaining|整数或 null|合法调用时减少|不因失败画面重开而重复增加|
|cooldown_until|周期/本地刻度|合法调用时写入|预览和预留不启动冷却|
|reserved_expedition_id|可空字符串|预留、出发锁定、释放|不能跨远征复用旧 reservation|
|effect_version|稳定版本号|效果实例化时|用于日志和迁移审计|
|last_result_id|可空字符串|结算幂等提交时|重复请求只返回旧结果|

每名 NPC 的 `uses_remaining`、`cooldown_until`、债务、人情和政治反馈独立保存。
R05-15：不存在“全 NPC 共用三次支援”或“联络位就是次数条”的共享资源解释。
联络位限制同时准备多少名 NPC；NPC 次数限制该 NPC 的能力可调用多少次；两者不可互相替代。

## 4. 联络位、预留与出发锁定

R05-16：正式版初测开放一联络位；容量是可同时准备的 NPC 数，不是 NPC 的使用次数。
在 `PREPARING` 中点击联络只建立 `reservation_id`、费用预览和支援目标，不扣资金、不扣补给、不减次数。
预留会显示计划占用，使玩家不能误以为余额足够；但账本余额仍保持原值，取消必须完整释放预留。
R05-17：玩家可以在 `PREPARING` 取消预留并改选另一名 NPC；取消不得留下费用、冷却、使用次数或政治痕迹。
从 `PREPARING` 进入 `PREP_LOCKED` 时校验队伍、任务、carry、条件和计划成本，但只锁定计划。
进入 `EXPEDITION` 的出发事务锁定所选 NPC、`support_id`、队伍快照和远征 ID；出发后不能换 NPC。
出发后若玩家未调用支援，预留保持为本次远征的未调用选择，并在合法释放点恢复 `available`。

|阶段|允许操作|不允许操作|成本状态|
|---|---|---|---|
|PREPARING|查看、预留、取消、换 NPC|调用仅限尚未到合法触发点的效果|仅预览，不扣费|
|PREP_LOCKED|确认出发配置、校验计划|换 NPC、改主任务、绕过校验|仍未扣费|
|EXPEDITION/NODE|执行节点支援、保留撤退|换 NPC、改已锁定队伍|按调用点原子扣费|
|EXPEDITION/COMBAT|执行一项高影响干预|再开第二项高影响干预|按战斗调用点原子扣费|
|RESULT_PENDING|结算前医疗和回城危机服务|改变胜负、目标 flags、战棋结果|医疗看携带，危机付回城代价|
|SETTLED 以后|查看记录、推进回响|追溯调用旧支援|不得改写已提交结果|

## 5. 调用时机、费用与原子提交

R05-18：费用只能在支援“合法调用”时与效果写入同一事务；预览、鼠标悬停、预留、取消都不扣费。
每次调用先校验阶段、NPC 锁定关系、目标节点、剩余次数、冷却、资金、补给和 carry。
校验失败时不写费用、不减次数、不写效果、不推进冷却，并返回可读的失败原因。
校验通过后同一提交包含 `fee_debit`、`uses_delta`、`cooldown_write`、`effect_instance` 和调用日志。
任何一个子写入失败，整笔事务回滚；不可出现“钱扣了但效果没有”或“效果生效但次数没减”。

|支援类别|合法调用点|主要效果边界|回滚观察点|
|---|---|---|---|
|出发准备|出发事务确认时|情报、工具、伪装进入快照|出发失败则整笔不落账|
|地图干预|`EXPEDITION/NODE` 解决节点前|开路、识别、撤退点或环境改变|节点未提交不得扣费|
|战棋干预|`COMBAT` 开始或明确回合窗口|部署、增援、医疗窗口、交涉窗口|战棋请求失败不改变结果|
|回城危机服务|撤退/失败已确定且回城前|资金、政治、债务或伤势善后|不能改目标和胜负|

情报型支援可以新增 `fact_id`，但不删除既有事实；若动作消耗时间或补给，消耗记录写入行动账本。
物理药品和工具必须在出发快照中占用 carry；结果结算前能改变伤势的只有已携带且可用的医疗物品。

## 6. 高影响干预与多个效果优先级

R05-19：每次远征最多提交一项高影响干预；这是远征级上限，不是所有 NPC 共用的次数条。
高影响干预实例记录 `expedition_id`、`npc_id`、`support_id`、触发阶段和 `effect_instance_id`。
同一 NPC 仍按自己的次数与冷却运行；一次远征限制为一项，不会把 NPC 的剩余次数重置或合并。
同一支援可包含多个声明效果，但必须在内容配置中标明主效果、伴随效果和互斥效果。
低影响的出发信息、日志提示或已携带普通物品不自动占用高影响干预位，仍需付各自明示成本。

优先级固定为：`硬性安全边界 > 目标存续/撤离 > 关键状态转换 > 资源转化 > 信息增益 > 叙事附加效果`。
同层效果冲突时，先按玩家明确选择，再按支援配置优先级，最后按稳定 `effect_id` 排序；不得按随机顺序。
两个效果若修改同一字段且没有显式叠加规则，后提交者不能覆盖前者，调用应提示互斥并拒绝。
“医疗保命”不能同时被解释为“证据自动带回”；“开路”不能自动改写战斗胜负或目标完成。

## 7. 职业与资源独立的基础主线路

R05-20：主线关键目标必须拆成事实门槛、行动门槛和结果门槛；特殊 NPC 只提供替代手段或更低代价。
推荐职业是 UI 解释和风险提示，不是硬条件；任何四名初始成员的合法编组都应能找到至少一条基础操作。
职业差异可改变耗时、风险、伤病概率或可选叙事，但不能单独决定主线是否可启动或是否有通行旗标。
资金、补给、carry 和声望影响可选方案；最低方案不能要求玩家先刷一项资源或完成一条 NPC 支线。
基础方案的成本可以更高、信息更少、战棋更难或只能得到部分成果，但必须显示代价和结果出口。

|主线闸门|无 NPC 基础做法|推荐职业带来的变化|资源不足时的出口|
|---|---|---|---|
|确认目标|固定来源的调查节点、普通成员观察或公开委托信息|提前识别风险、少走一段路线|接受更多 `local_tick` 或风险，不隐藏目标|
|进入区域|普通路线和已知边缘入口|开捷径、减暴露或减补给|走长路、消耗明确补给或选择回撤|
|处理关键障碍|基础工具、队伍协作、可承受战棋|改变部署或取消一项环境压力|保留次要目标，进入部分成功|
|带回结果|携带证据并从可通行出口撤离|建立安全撤退点或减少损失|事实保留，物理证据按携带和撤离判定|

## 8. 无 NPC、低资源与全员受伤覆盖矩阵

下表是基础解法的强制覆盖矩阵，不是 DEMO 的节点或单位配置；每格都要有可追踪的结果出口。

|场景组合|允许的基础路径|必须承担的代价|禁止行为|验收焦点|
|---|---|---|---|---|
|无 NPC|公开情报+普通职业动作+基础路线|更长 `local_tick`、更高风险或少一个可选奖励|把 NPC 设为唯一钥匙|TC05-01|
|无推荐职业|任意合法队伍走通通用动作|多一次判定、补给或伤势风险|职业硬锁主线|TC05-02|
|资金低于准备包|免费/低费基础准备或延后出发|风险、债务或政治可预告|强制购买 NPC 服务|TC05-03|
|补给低或为零|节省路线、基础休整、撤退或部分目标|耐久、伤病、时间和奖励降低|用隐藏补给补足|TC05-04|
|carry 已满|舍弃非关键物、分段带回或无物理证据路线|证据可能无法取出|自动扩大容量|TC05-05|
|部分成员受伤|未伤成员承担任务，伤员进入恢复|恢复时间、队伍能力下降|为了推荐职业强派伤员|TC05-06|
|四名初始成员全员受伤|全员进入恢复事务，不硬出战；主线可暂停并保留明确补救入口|`local_tick`、周期维护或公开的世界压力|自动强制出战、随机永久损失|TC05-07|
|无 NPC+低资源+全员受伤|安全回城/基础恢复/固定线索保留，恢复后再走基础路线|至少一项可见时间或危机代价|软锁、要求付不起的费用|TC05-08|

“低资源”按当前任务所需成本不足判定，不新增隐形负债；恢复事务必须说明是否增加本地刻度。
全员受伤时，`PREPARING` 提供“恢复并延后”而非“选择一人硬上”；延后后保留已知 facts 和任务状态。
若主线现场只剩战棋，玩家可接受“未完成/撤退”结果并回城，不能因全员受伤卡在战棋入口。

## 9. 关系路线与支援强度

R05-21：友情、合作、恋爱都至少包含完整的支线阶段、早期能力体验、一次明确选择和非完美结局。
三条路线的差异在叙事立场、代价形态、对话和结局，不以恋爱路线垄断最高强度玩法。
每个 NPC 使用 `route_progress[npc_id][route_id]`；不建立跨 NPC 的 `global_affection_pool` 或共享上限。
同一 NPC 的路线锁定必须由玩家明确选择并提示影响；未锁定前不因普通合作、使用支援或完成任务暗中转入恋爱。
友情与合作可以给出等强度的情报、工具、地图或危机能力；效果形式不同但不能只是低配安慰奖。
普通冒险者的队伍标签只影响短期氛围或日志，不产生主角好感，也不与 NPC 路线争抢资源上限。

## 10. 失败窗口、重试与结算边界

R05-22：从战斗开始到结果确认存在明确失败窗口；玩家可在窗口内接受结果或使用合法的免费重试。
免费重试不是作弊：它完整恢复 `combat_start_snapshot`、战斗随机状态、战斗支援配额和战斗内临时状态。
重试不恢复战斗前已经使用的地图助力；地图干预属于更早的节点事务，必须保持已付代价和已写地图状态。
重试不产生新奖励、不推进 `world_cycle`、不复制费用返还以外的收益，也不改变主线 facts 的既有获取记录。
一旦玩家接受结果并进入 `RESULT_PENDING`，不能再换 NPC、重开战斗或用支援改写目标 flags 与胜负。
结算前只有出发时携带并仍可使用的医疗能改伤势；其他危机服务只能在回城窗口付政治或债务代价。
危机服务可以提前预告可用条件和后果，但不能被一概禁止为“保险”；它不能抹除撤退、失败、证据丢失或政治后果。

`result_id` 是结果提交主键；重复请求同一个 `result_id` 必须返回第一次提交结果，不得重复增减资源、次数、伤病或奖励。
存档只允许在相同 `settlement_epoch` 内整包替换；正式结算后旧手动档标记为只读历史，不与当前档跨阶段 merge。

## 11. 具体实例与制作解释

实例 A：无 NPC、没有推荐职业且资金不足时，队伍读取公开事实，走长路线，保留主目标并承担额外刻度；这不是失败锁。
实例 B：地图上已调用向导开撤退点，随后战棋失败并免费重试；重试恢复战斗快照，但撤退点仍已使用且不返还次数。
实例 C：医师支援处于 `reserved`，玩家在出发前取消；资金、次数、冷却、联络位全部释放，不能留下“已使用”日志。
实例 D：战棋中调用外交家开交涉窗后再请求第二项高影响干预；第二次被拒绝，第一次的费用和效果不回滚。
实例 E：四名成员全员受伤且补给为零；系统进入恢复路径，允许周期结束并保留 facts，不强派任一人进入战棋。
实例 F：同一 NPC 的友情路线和恋爱路线都能完成；一条不因另一 NPC 已有友情进度而被全局上限截断。

## 12. 验收用例（只定义，不代表已执行）

TC05-01：删除全部 NPC 解锁与联络位，主线仍能从目标确认到至少一个合法结果出口。
TC05-02：用非推荐职业编组完成同一闸门；记录风险/成本差异，不出现职业硬锁。
TC05-03：资金不足以购买推荐包时，能看见基础准备、延后或债务/政治出口，不能无提示卡死。
TC05-04：补给为零时，进入节省、撤退、恢复或部分成功路径；补给不被 UI 预览偷偷增加。
TC05-05：carry=10 已满时，物理证据与事实线索分开判定，舍弃证据不会删除已获得 `fact_id`。
TC05-06：一名成员受伤时不强制该成员出战，仍有合法队伍选择和恢复记录。
TC05-07：四名初始成员全部受伤时，选择恢复不会生成强制战斗，也不会进入不可恢复状态。
TC05-08：无 NPC、低资金、零补给、全员受伤组合连续走一轮，能到达周期关闭或明确补救入口。
TC05-09：预留后取消，逐项比对资金、补给、次数、冷却、联络位和日志均未产生实际消耗。
TC05-10：同一远征尝试两项高影响干预，第二项被拒且不重复扣费；不同 NPC 的剩余次数仍分别正确。

## 14. 结论

支援系统的核心不是让玩家拥有更多按钮，而是让同一个目标出现更清晰、更有代价的解决路径。
联络位负责“本次准备谁”，NPC 个人次数负责“这个人还能帮几次”，远征高影响槽负责“本次最多改变一次核心局面”。
基础主线负责保证没有 NPC、没有推荐职业、低资源和全员恢复时仍有可理解的下一步。
任何未来数值调整都必须保留上述契约、状态时机、幂等边界和覆盖矩阵。
