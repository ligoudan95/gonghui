### 完成内容

- **第十二批中断点续查**，本机（A 机）全新路径排查，全程用户在线拍板（装插件实弹 → 修复 0.3.0 再实弹）。
- **纠正排查入口**：hook runner 真本体不在 app.asar 的 out/ 代码，而是 `F:\新建文件夹\ZCode\resources\glm\zcode.cjs`（14.8MB CLI 核心 bundle，module 名 `core.hooks`）。app.asar 里只有 workspace-hook 信任审核的 UI schema。asar 解包在 Windows 会丢文件（27068/30165），须用 node 直读 asar 内容扫描。
- **实弹复现**：本机 3.14.0 装插件 0.2.0 重启后（hookCount 0→2，装载成功），AskUserQuestion 前后 Pre/Post 各一条 `hook.run.failed`（31/30ms 秒败）——与 liangqihang 机 0.16.9 症状完全一致 → **版本假说推翻，是共性根因**。3.14.0 失败时 logger.warn 落盘字段不含 errorMessage（错误详情只进遥测 emitHookEvent），日志依旧无详情。
- **根因定论（决定性实验证实）**：hooks.json 写 `shell:"bash"` 时 spawn 靠 **PATH 裸名解析 bash**；Windows 的 Git 安装器默认只把 `<Git>\cmd` 加入系统 PATH，**该目录没有 bash.exe**（bash 在 `usr\bin`、`bin` 子目录，均不进系统 PATH）；ZCode.exe 桌面启动继承系统 PATH → `spawn bash ENOENT` → 30ms 级秒败。模拟系统 PATH（仅 System32+Git\cmd+node）实测：shell:"bash" → ENOENT 4ms 复现；shell:true（cmd）→ 66ms 成功；process 型 node+args → 47ms 成功。
- **解释了历史全部现象**：两台机器（Git 分别在 F:\Git 与 C:\Program Files\Git，位置无关）同症；godot-prompter SessionStart hook 同败（同类写法）；历批"冒烟测试全过"却线上秒败——终端会话 PATH 含 usr\bin（bash 可解析），与桌面进程的 PATH 不同，系统性测试盲区。
- **3.14.0 源码能力确认**：`${CLAUDE_PLUGIN_ROOT}`/`${ZCODE_PLUGIN_ROOT}` 等占位符展开**覆盖 process 型的 command 与每个 args 元素**（Xge 调用处证实），子进程 env 注入完整变量组（Thn）；bash 候选硬编码 `C:\Program Files\Git\bin\bash.exe` 仅用于 posix-bash profile 分支，不救 shell:"bash" 字符串。
- **修复 0.3.0（已实施待实弹）**：hooks.json 改 process 型 `command:"node"` + `args:["${CLAUDE_PLUGIN_ROOT}/hooks/<脚本>"]`（node 在两台机器 PATH 均验证存在），删多余 `bash` 字段（3.14.0 单条 hook schema 为 strict 模式，未知字段有被拒风险）；plugin.json 与 marketplace.json 版本同步 0.3.0。
