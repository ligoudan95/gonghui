# 案 15《UI/UX 与双端适配规划案》

## 1. 系统定位与目标

- **定位**：全部系统案的呈现层规范——横屏双端同版（已定稿）下的屏幕清单、触控规范、信息可读性规范与真机验证计划；DEMO 直接使用；
- **服务的核心体验**：三支柱的体验质量下限（战棋操作精度与文本可读性是移动端成败点）。

## 2. 机制细则

### 2.1 已定稿约束（入档）

**横屏双端同步开发；UI 触控优先、双端同版**（Steam + TapTap）。

### 2.3 触控设计规范（推断建议，占位基准）

- **最小点击热区**：48×48 逻辑像素（战棋格子与按钮不低于此）；
- **双手持机操作区**：高频操作（移动确认/技能/待机）置横屏下方左右拇指弧区；信息浏览区置上方；
- **防误触**：高成本操作二次确认（招募/出征）；技能目标选取支持取消返回；
- **移动路径预览**：确认后执行；「移动后反悔」留试玩验证，DEMO 先做「未确认前可重选」。

### 2.4 信息可读性规范（推断建议）

- 正文字号下限：移动端等效 16-18px，随分辨率基准缩放；
- 战棋单位信息密度：默认仅血条+资源条+状态图标；点选/长按展开完整信息卡；
- 状态图标+Tooltip：一律图标化（正负配色），移动端**长按**、PC **悬停**触发详情；
- 事件文本滚动区固定高度，选项文字完整显示不截断。

### 2.5 双端同版策略（推断）

- 以移动端横屏为基准分辨率设计，PC 等比放大；鼠标与触控事件等效映射；无平台独占 UI（差异仅输入方式与悬停提示）。

### 2.6 真机验证计划（推断）

- M0 战棋原型即上移动端真机；每个构建里程碑双端各过完整流程并记录操作摩擦点清单；重点专项：D20 演出节奏、回合序条可读性。

## 3. 数据与配置需求（规范级草案）

UI 屏幕清单表（屏幕 id/名称/挂接系统/DEMO 标记/布局基准）、触控规范参数表、可读性参数表、资源规范（统一走案 16 引用规范）。

## 4. 与其他系统的接口

- **输入**：全部系统案的展示需求（2.2 清单）；**输出**：统一交互事件（点击/长按等效映射）；**依赖**：案 16；**被依赖**：全部系统案（呈现层）。

## 5. DEMO 口径

- **做**：2.2 清单全部「含」项；触控与可读性规范执行；双端真机过流程；
- **不做（暂缓）**：商店/生产/祷告界面、完整悔棋、多语言、云存档类平台功能。

## 6. 风险与待专项细化项

- **风险**：① 战棋在手机屏的操作精度与信息密度平衡（DEMO 头号验证点）；② 双端同版致 PC 体验「手机化」（接受——已定稿触控优先）；③ 演出拖沓破坏心流（掷骰/结算动画可跳过开关——已列入设置清单，照改）；
- **待专项细化**：视觉专项案（界面概念稿/图标体系）；真机摩擦清单迭代机制。
