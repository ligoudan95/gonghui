# 案 2《时间与日历系统规划案》

## 1. 系统定位与目标

- **定位**：全局唯一时间标尺——经营（生产/休息/招募刷新）、委托（时限倒计时）、冒险（出征耗时）全部挂在此标尺上；提供「日结算」统一调度点，杜绝各系统各自计时导致的时序混乱。
- **服务的核心体验**：委托时限的紧迫感与经营节奏感（「今天该接哪单、派谁出门、家里谁在休息」的日程决策）。

## 2. 机制细则

### 2.1 日历制定义（已定稿）

- 以**「天」**为最小单位；委托以剩余天数倒计时，到时刷新、消失或替换（原文）。
- **推进方式（推断建议）**：**行为驱动、非实时流逝**——天数只在发生「耗时行为」时推进，玩家不行动时间不走（无真实时间压力，契合单机与移动端碎片化节奏）。
- 历法显示（推断）：以「第 N 天」计数为主，可选七日一周的星期展示增强经营氛围；不设季节/昼夜系统（完整版可选扩展，DEMO 外）。

### 2.2 时间消耗行为表（推断建议）

| 行为 | 时间消耗 | 规则说明 |
|---|---|---|
| 出征探索 | 1 天起，按区域远近/委托规格累加 | 出征为「离城」状态；期间公会后台事务并行推进（见 2.3） |
| 战旗战斗 | 不单独耗天 | 含在出征日内（避免频繁跳日破坏节奏；高强度战斗是否+1 天留数值专项验证） |
| 事件检定/分支 | 不单独耗天 | 部分事件选项可标注「耗时+1 天」类代价（推断：作为事件资源之一，归案 8） |
| 设施生产下单（暂缓） | 按配方天数 | 下单后后台推进，完成于日结算时交付 |
| 冒险者休息/重伤休养 | 按天 | 指派制，每日日结算时恢复 |
| 招募池刷新 | 每日 | 日结算时刷新 |
| 委托倒计时 | 每日 -1 | 日结算时结算，归零触发到期处理 |
| 公会内管理操作（接委托/编队/浏览/交易） | 0 天 | 管理行为不耗天，保持节奏流畅 |

### 2.3 并行规则（推断建议）

- **出征日 = 公会后台日**：小队出征消耗的天数内，公会中的生产、休息、休养照常逐日推进（玩家回城时一次性看到后台结算结果）；
- **多小队**：每支小队每日最多一次出征；多队先后出征时天数累加推进（A 队 1 天 + B 队 1 天 = 日历+2，后台事务按 2 天结算）；
- 一天内「出征 + 回城管理 + 再次编队」允许（只要该队当日未再出征）。

### 2.4 日结算流程（固定顺序，推断建议）

```
1. 天数 +1，日历刷新
2. 进行中的设施生产推进/完成交付（暂缓系统，DEMO 跳过）
3. 休息/休养中的冒险者恢复结算（宿舍效率加成，案 3/5）
4. 压力/怪癖每日结算（暂缓系统，DEMO 跳过，案 14）
5. 招募池刷新（案 5）
6. 委托倒计时 -1 → 到期委托处理（见 2.5）
7. 日期触发的剧情/节日事件检查（暂缓系统，DEMO 跳过，案 13）
8. 汇总通知（新一天提示：生产完成/恢复完成/委托到期/新候选，单弹窗汇总避免打扰）
```

### 2.5 委托到期处理（原文+推断细化）

- **板上未接委托**到期：从委托板移除，同日生成新委托补位（「刷新/消失/替换」三种表现由委托模板配置决定，归案 6）；
- **已接取未完成委托**到期：自动判定失败（推断建议）——小队自动回城、无报酬；是否扣声望及数额留数值专项案（DEMO 内建议无惩罚，降低学习成本）。

### 2.6 时间上限

无全局天数上限、无整体倒计时（推断：单机自由节奏；完整版主线是否设节点时限归案 13 另议）。

## 3. 数据与配置需求（字段级草案）

| 配置 | 字段建议 |
|---|---|
| 总控时间配置 | 起始天数、星期显示开关（七日循环）、结算顺序 pipeline（阶段 ID 列表，支持插拔暂缓项） |
| 行为耗时表 | 行为 ID、基础天数、区域/规格修正字段（对接案 7 区域表与案 6 委托表） |
| 生产配方耗时（暂缓，存档） | 配方 ID、耗时天数（对接案 4） |
| 委托时限（归案 6，本案引用） | 委托模板.剩余天数初值、到期行为（刷新/消失/替换） |
| 招募刷新（归案 5，本案引用） | 刷新周期（天）、池容量 |

## 4. 与其他系统的接口

- **输入**：各系统申报的耗时行为（出征耗时←案 7/6；生产下单←案 4；休息指派←案 5）；
- **输出**：日结算广播（按 2.4 顺序逐项通知）：生产完成→案 4；恢复完成→案 5；池刷新→案 5；委托到期→案 6；日期事件→案 13；
- **依赖**：无上游（全局基础）；
- **被依赖**：案 3（生产/休息效率结算时机）、案 6（倒计时）、案 5（恢复/刷新/休养天数）、案 7（出征耗时）、案 4/14（每日结算挂点）。

## 5. DEMO 口径

- **做**：天数推进（行为驱动）、星期显示（可选）、日结算流程的 1/3/5/6/8 步（跳过暂缓步）、委托倒计时与到期处理（板上刷新替换；已接到期失败且无惩罚）、出征耗时（矿洞单次出征固定 1 天，占位）、休息按天恢复；
- **不做（暂缓存档）**：生产耗时结算、压力怪癖每日结算、日期剧情/节日事件、事件选项「耗时」代价、多档区域耗时修正；
- DEMO 验证点：日结算汇总通知是否清晰、出征跳日的节奏感受。

## 6. 风险与待专项细化项

- **风险**：① 出征日并行推进的后台结算对玩家不透明（界面必须清晰展示「离家期间公会发生了什么」，UI 归案 15）；② 多队连出征造成天数快速堆积，委托时限压力失衡（数值匹配验证）；③ 日结算顺序变更会引发连锁时序问题（顺序表进配置而非硬编码）；
- **待数值专项案**：各行为具体耗时、区域耗时修正、委托时限与耗时的匹配曲线、已接委托到期失败的声望惩罚值、休养天数。
