# 案 16《内容数据与配置化规划案》

## 1. 系统定位与目标

- **定位**：全项目数据层统筹规范——前 15 案所有数据表的汇总目录、冲突校验、组织方案与引用完整性规则；DEMO 直接使用（各案建表以本案为总纲）；
- **服务的核心体验**：无直接体验承载；服务内容量产效率与长期维护成本。

## 2. 机制细则

### 2.1 表驱动总原则（入档）

**内容与逻辑分离：调整内容不改程序，扩充内容不动框架**；DEMO 数据结构按完整版标准（范围可小、结构不能歪）。

### 2.3 冲突与重复校验（修正建议）

1. **职业定义表**：案 5 建立+案 10 补充 → **单表合并**，字段=案 5 全部+案 10 扩展，案 5 主责；
2. **生产耗时**：案 2 与案 4 重复 → 耗时字段**唯一归属案 4 配方表**，案 2 行为耗时表仅管通用行为；
3. **开局参数包**：双处描述 → 定义与默认值**唯一权威=案 9**（参数清单源自案 8 §2.5 六维度）；
4. **委托时限**：唯一归属案 6（确认无冲突）；
5. **状态定义**：案 11 唯一中枢；案 14 复用需扩展**持续时间类型**与**移除方式**两字段（预留，启用前落实）；
6. **掉落表**：唯一归属案 4；
7. **恢复数值**：口径=**基础值（案 5）× 系数（案 3）**，字段命名对齐；
8. **出征耗时唯一归属（照改裁定）**：案 7 地图定义「基础出征耗时」为唯一权威；案 6 委托模板「预估出征耗时」仅展示用；案 2 行为耗时表只留通用行为定义。总出征耗时=基础出征耗时+Σ事件耗时（案 8）（#3）。

### 2.4 数据组织方案（推断，供架构参考）

- **目录按域分组**：`data/core`、`data/guild`、`data/adventurer`、`data/quest`、`data/map`、`data/event`、`data/battle`、`data/status`、`data/economy`、`data/class`（职业/技能/倾向/二转）、`data/world`（区域/场所/NPC 摆位）、`data/stress`（压力/怪癖）、`data/story`（存档）、`data/ui`；
- **资源引用规范**：表内只存资源 id（小写下划线命名），路径映射集中管理一处，禁止表内写死路径；
- **热重载方向**：开发期配置热重载（供架构参考的策划需求）。

### 2.5 DEMO/完整版模式开关

总控配置（对齐案 1）：模式标记 + 系统启用清单（暂缓系统整块关闭）；各系统启动时读清单决定挂载。

### 2.6 数据校验方向（引用完整性检查清单，推断）

| 链路 | 检查项 |
|---|---|
| 委托→事件链→节点→选项 | 引用存在；去向节点存在或出口合法 |
| 选项→出口 | 参数包字段合法（六维度枚举）；奖励引用存在；D 类出口 DEMO 模式被启用清单拦截 |
| 委托→地图 | 目标地图 id/目标点/采集点存在且与 goal_type 参数匹配；需求人力区间合法（1 ≤ 下限 ≤ 上限 ≤ 4）；编队人数 ∈ 该委托区间 |
| 地图交互点→事件 | 事件链 id 或单点事件 id 存在（村子轻事件=单点事件） |
| 事件授予委托→委托模板 | 委托模板 id 存在（C8 端口；DEMO 演示 1 处需校验） |
| 事件金校验口径（P-11） | 事件金校验按**基础值**校验（单出口基础金 ∈ 配置域 [5,30]）；修饰性叠加（如 E3a 30+20=50 金的选项叠加）不计入域校验；0 金合法（字段缺省=无货币出口） |
| 委托→目标点（P-9） | 板刷模板 explore 判据的 tp_mine_* 目标点 id 在案 7 目标标记点列表中存在且匹配（5 点全登记） |
| 委托→敌方配置（P-9） | 板刷模板 clear 判据的 enc_m1_lair_pack 敌方配置 id 在案 9 敌方队伍配置/案 17 §3.8 中存在 |
| goal_type 参数完整性 | 清怪=敌方配置引用/探索=目标点 id/收集=物品 id 与数量/护送=护送终点 id（案 6） |
| 委托类型/执行大类枚举 | 执行大类枚举（战斗/非战斗）为独立字段，与类型枚举分开校验；非战斗（存档）——DEMO 模式被启用清单拦截（#24） |
| 地图/委托→区域 | 区域 id（或列表各项）存在于案 12 区域表（唯一权威） |
| 区域-地图映射 | 单向：仅地图侧持有（案 7），区域侧列表为派生查询不落盘（P3） |
| 技能→状态/地格 | 状态 id 存在且来源允许；地格引用案 9 格子类型 |
| 技能→属性权重表 | 属性 id 合法、权重非负（权重和校验归数值专项案） |
| 状态施加链 | 两段判定读数属性存在（命中率/异常状态抗性，案 5） |
| 状态→互斥组 | 组 id 存在；组内无同名 |
| 敌人→技能/掉落 | 引用存在；掉落物品 id 存在（案 4）（DEMO：掉落表纯存档，掉落引用字段允许空值） |
| 敌人→种族/系别标签 | 枚举合法 |
| 敌人 AI 层级 | AI 层级枚举合法（L1-L4，案 21） |
| Boss 脚本→技能/召唤/状态 | 引用存在（案 21） |
| 免疫组→互斥组/大类 | 组 id/大类 id 存在（案 21） |
| 配方/装备→物品/词条 | 原料与产出 id 存在 |
| 装备→槽位 | 四槽枚举合法（案 4） |
| 倾向→技能池 | 引用存在且档位合法 |
| 冒险者→职业/技能/装备 | 引用存在；资源类型与职业法系/物理口径一致 |
| 委托→获取渠道 | 事件授予专用模板不入周刷新生成池（案 6） |
| 事件奖励数值域 | 经验 ∈ [10,20]、金币 ∈ [5,30]、声望展示 ≤2、事件耗时 ∈ {0,1}（案 18） |

## 3. 数据与配置需求

本案自身即数据总纲（2.2 为唯一权威清单）；新增数据表须经本案登记。

## 4. 与其他系统的接口

- **输入**：全部前 15 案的数据需求节；**输出**：总目录与校验规则→架构师（程序方案阶段直接输入）；模式开关→全部系统启动流程；
- **依赖**：全部前 15 案；**被依赖**：全部系统案、后续专项案。

## 5. DEMO 口径

- **做**：建全部「DEMO 必建」表（子集数据）与「先建后空」表结构；目录与引用规范落地；模式开关；引用完整性检查跑通委托→事件→战斗全链路；
- **不做（暂缓）**：纯存档表不建（仅文档级草案）；热重载视架构成本裁剪（最低要求重启生效）。

## 6. 风险与待专项细化项

- **风险**：① 表结构中期变更的连锁返工（2.3/2.6 是防线，架构阶段落为自动检查）；② 「先建后空」表被误当已实现（启用清单严格隔离）；③ 资源 id 命名混乱；
- **待专项细化**：架构师对组织方案/热重载/校验的可行性裁定；数值与事件文案专项案按本案目录填充。
