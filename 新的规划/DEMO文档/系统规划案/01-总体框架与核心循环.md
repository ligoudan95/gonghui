# 案 1《总体框架与核心循环系统规划案》

## 1. 系统定位与目标

- **定位**：全部 16 个系统案的总纲——定义游戏定位、三层玩法循环、系统关联依赖、DEMO 范围总控与风险归属。本案不实现为具体程序模块，是其余 15 案的上位依据与冲突仲裁基准（任一系统案与本案冲突时，以本案为准或回到用户裁决）。
- **服务的核心体验**：三支柱（当会长的养成感 / 掷骰抉择的代入感 / 小队战棋的策略感），咬合点为「冒险者是贯穿三层的唯一载体」。

## 2. 机制细则

### 2.1 游戏定位（继承 v0.4 第一章，已定稿部分加粗）

- 类型：冒险公会模拟经营 + 属性鉴定类 CRPG 多分支 + 局内战旗；
- **当前体量定位：DEMO（剧情暂缓；完整版规划待 DEMO 验证后另立）**；
- **付费模式：无内购单机**；平台：**Steam + TapTap 横屏双端同步，UI 触控优先、双端同版**；引擎 Godot 4.7.2；美术：二次元 + 日式奇幻。

### 2.2 核心体验三支柱

1. 当会长的养成感（经营层承载）；2. 掷骰抉择的代入感（冒险层承载）；3. 小队战棋的策略感（战旗层承载）。

### 2.3 循环体系

**大循环**：

```
经营层（光辉城/公会）：查看委托 → 选择委托 → 派遣小队（≤4人）
  ↓
冒险层（野外地图·废都物语式）：格子探索 → 事件 → D20 检定/分支抉择
  ↓（检定结果改写战旗开局）
战旗层（局内小地图战棋）：速度排序 → 移动/地格/技能（双资源）→ 胜负
  ↓
结算反哺：佣金+素材+经验+声望 → 设施/招募/养成 → 公会等级 → 更高内容
```

**中循环（单次委托 8 步，推断）**：接委托（看剩余天数）→ 按检定需求编队 → 出征探索（耗天）→ 事件分支+检定（自动取最高可改派）→ 检定结果改写战旗开局 → 战旗战斗 → 结算（胜：报酬掉落经验声望；败：重伤休养+压力惩罚【压力部分暂缓】，无永久死亡）→ 回公会消费与休整。

**小循环**：
- 战旗回合循环：回合开始 → 按速度（敏捷换算）逐单位行动（移动+行动）→ 敌方 AI → 回合末结算持续效果与地格效果；
- 探索检定循环：踩格/交互触发 → 事件面板（标注属性与难度）→ 掷 D20 → 四档结果反馈（大成功/成功/失败/大失败）。

### 2.4 系统关联依赖图（案号按批准版目录标注）

```
公会等级（案3）──上限──> 六设施等级（案3）
     ▲  │
     │  └──解锁──> 同档高奖励委托（案6）/ 稀有委托 / 主线章节（案13，暂缓）/ 区域（案7/12）
声望+考核委托（案6，双轨升旗；考核暂缓）
     │
委托完成（案6）──资金+素材+声望──> 经营投资：设施（案3）/招募（案5）/生产链（案4，暂缓）
     │
派遣小队（案5，≤4人）──七属性──> 探索检定（案8：D20·自动取最高可改派）
     │                              │
     │                      检定结果改写战旗开局条件
     │                              ↓
     └────────────────────> 战旗局（案9：敏捷速度/移动力/地格；案10：职业与技能；案11：状态效果 BUFF/DEBUFF；双资源见案5）
                                    │
结算 <──────────────────────────────┘
  ├─ 佣金/素材/经验/声望 ──> 案6/案4/案5/案3
  ├─ 重伤休养（案5）──> 宿舍休息（案3）──> 再出征
  ├─ 压力/怪癖（案14，暂缓）──> 祷告室（案3）──> 轮换
  └─ 主线进度（案13，暂缓）──> 路人台词/城主大厅/新区域
时间标尺：全流程挂在日历制（案2）之上
幸运属性横跨：检定大成功倾向（案8）/ 暴击掉落（映射骨架见案5，系数归数值专项案）/ 赌箱（案4，暂缓）
职业属性倾向覆盖（案10）：六职业覆盖七检定属性 → 自然混搭引导
```

**关键咬合点**：① 冒险者作为三层唯一载体；② 职业属性倾向覆盖→检定优势→自然混搭；③ 检定结果改写战旗开局；④ 素材→生产设施→战旗补给（暂缓但设定保留）；⑤ 压力怪癖→祷告室→轮换（暂缓但设定保留）。

### 2.6 DEMO 范围总控（继承 v0.4 第八章，正式入档）

- **目标**：验证「单次委托完整循环」是否好玩 + 战旗手感、D20 检定趣味两个单点；
- **包含**：日历时间、委托板（普通委托 4-6 模板/1 档/到期刷新）、宿舍 1-2 级、训练场 1-2 级（第 1 档技能+板凳分享）、简化招募（固定 4 人初始队+少量候选）、野外图 1 张（村子+矿洞一层：格子揭示/事件点/宝箱/暗门 1 处）、事件链 2-3 条×3-5 分支、D20 检定全套、战旗图 2-3 张（六职业各 1-2 技能、基础地格、双资源、BUFF/DEBUFF 基础池）、结算反哺闭环、战败重伤休养、**最简自动存档（日结算/关键节点自动保存——用户 2026-09-20 拍板新增）**；
- **不含（暂缓）**：剧情全套（主线/暗线/多结局/路人/城主大厅/NPC 入会）、四生产设施与消耗品链、压力与怪癖、二转、稀有/考核委托与升旗、最强装备、大森林、光辉城其余五场所、永久死亡开关；
- **最小可玩组合**：初始 4 人（覆盖 4 职业）→ 接 1 委托 → 矿洞一层（2-3 检定+1 战旗）→ 结算 → 公会消费 → 下一委托；单循环 20-40 分钟、总计 2-4 小时（占位）；
- **构建顺序**：① 战旗手感原型 → ② 检定事件原型 → ③ 组装循环 → ④ 双端触控验证贯穿。

## 3. 数据与配置需求

本案为总纲，无独立数据表；要求：16 案各自的「数据与配置需求」节字段不得相互冲突，冲突时以本案依赖图与职责边界为准。全局配置建议设一份总控配置（DEMO/完整版模式开关、系统启用清单），使暂缓系统可整块关闭（供架构师参考；配置化规范统筹归案 16）。

## 4. 与其他系统的接口

- **输入**：无（上位文档）；
- **输出**：定位与循环约束（下发全部 15 案）、依赖图与职责边界（冲突仲裁依据）、DEMO 总控（范围裁剪基准）；
- **被依赖**：全部系统案。
