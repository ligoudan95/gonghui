## 一、风格总纲（案 20 §2.1/§2.2/§3.4 提炼）

- **画风**：赛璐璐平涂——清晰线稿描边 + 大色块 + 少量高光渐变；明度饱和适中、偏日式奇幻插画；**全项目不走像素风**（用户拍板 20-C1）。
- **单位形态**：Q 版二头身——大头身比、缩小躯体、放大武器与头饰特征（案 20 §3.4 推荐已采纳）；剪影辨识主力 = 武器形状 + 头饰/发型轮廓。
- **调性分区**（案 20 §2.4）：公会/光辉城 = 暖色市井（木色、炉火橙、灯火黄）；村子 = 田园（草绿 + 土黄，明亮少阴影 = 安全区视觉信号）；矿洞 = 冷暗岩穴（蓝灰冷色 + 火把橙点光源）。
- **阵营硬规则**（案 20 §3.4，运行时程序层实现）：我方 = 蓝底圈 + 蓝血条；敌方 = 红底圈 + 红血条；精英 = 金色描边框 + 体型放大约 150%（勘注·v1.1：运行时实值 = **1.3 倍**（`ELITE_SCALE`·`unit_badge.gd`）——「约 150%」为案 20 §3.4 原文口径，制作与验收以实值 1.3 为准）。底圈/血条/金框均为 UI 层程序化叠加，**不画入任何素材**；服装主体色不得与阵营红/蓝冲突。

## 三、描边与光影规范

- **线色**：统一 `#2E2620`（暖调深棕黑）；线条闭合不断线、无飞白。
- **线宽**（源尺寸下基准）：128 级素材（单位竖条/tile）3-4px；64 级图标 2-3px；1920 背景大件 6-8px；UI 件（面板/按钮/标签）2-3px。同组同批线宽一致。
- **光影**：赛璐璐二分（一亮面一暗面）+ 单层高光点缀；禁止多级软渐变、模糊阴影、噪点质感。

## 六、验收通用条款（全件适用）

1. **文件规格**（图像件适用；10 字体组为 ttf/otf 授权件，按该组验收条款执行）：PNG-24 无损（1920×1080 大背景可 WebP）；透明底（背景件按 01 组规定为不透明）；无压缩噪点。
2. **色板**：只用 §二色板（允许同色系明度过渡），描边与线宽符合 §三。
3. **跨件一致性（核心）**：同色板 + 同描边 + 同二分光影；单位件另须「同人同装」——同一单位 6 动作间，角色设定卡（04 组）逐项一致（体型/服装/武器/主色不变，仅运动部位变化）。
4. **单位件**：缩至 48px 高时职业/种类可辨（剪影 = 武器形状 + 头饰/发型轮廓，案 20 §3.4）。
5. **动作件**：宽 128、高 = 帧数×128、帧数∈规格带（idle[2,4]/move[4,6]/melee_attack[2,4]/cast_ranged[2,4]/hit[1,2]/downed[2,3]）——过 V-M6-anim-geometry 自动校验。
6. **tile 可平铺件**：128×128、四边无缝平铺；物件类 tile 轮廓不越 128 画布、底缘对齐格界。
7. **来源留档**：每件入库后回填 `art_source_log.md`；入库按 M6 方案 §3.2 八步执行（产出→切片→按 id 命名入 `assets/` 分组目录→sync 工具登记→selfcheck→目检→留档回填→同变更集提交）。
8. **战棋菱形件（E1 战棋等距批起·2026-10-09）**：战棋消费的 tile/叠加键源图 **256×128（2:1 等距菱形）**——菱形四顶点=画布四边中点（上/右/下/左）、**菱形满幅**、画布四角透明；物件件母题完整落于菱形内、底缘对齐菱形下缘；出图按 2:1 比例（如 1024×512）→ 缩放至 256×128；`fx_battle_range` 等染色叠加件的**净 α 全由运行时 modulate 承载**口径沿用（禁自带 α，见 09 组）；过 DataValidator `V-M6-iso-asset-geometry` 几何校验（17 键 256×128 断言）。菱形键全集：矿洞 `_iso` 5+村子 `_iso` 7+战棋状态同 id 重制 3（bush/highground/trap）+fx 重制 2（select/range）。

## 七、素材来源策略（AI 主通道）与商用合规

- **通道总策略**（案 20 §4.4 + M6 方案 §3.3；2026-09-30 D1/D2 用户拍板后修订）：
  - **唯一主通道 = AI 生图**：二次元为 AI 生成成熟度最高领域（立绘/背景/图标/Q 版单位覆盖度高）；
  - **02/03 tile 组 = 全 AI 生成+人工修整（D2=B 已拍板）**：零采购预算；tile 类为 AI 弱项（平铺无缝+批量一致难），由人工修整收敛；
  - **其余组购买通道仍开放（例外兜底）**：如遇 AI 无法达标的件可购买，以**风格对齐为第一标准**（色板/描边须与 AI 产出统一），购买件一律按 `art_source_log.md` 购买分区留档；
  - **占位兜底**：无素材时程序化占位件同 id 顶位，正式件到位原位替换、配置零改动（占位/替代/正式同 id——案 20 §4.3 总原则）。
- **商用范围**：Steam + TapTap。
- **合规注意**（案 20 §4.4）：Steam 自 2024 年起要求披露 AI 生成内容，TapTap 同类政策发布前查证；混用通道（AI+购买）须分别留档来源——统一登记于 `art_source_log.md`（AI 分区/购买分区），发布前披露清单见该文件汇总节。

## 九、id 命名规约与登记流程

- **资产 id 前缀**：`bg_`（背景）/ `tile_`（tile）/ `icon_`（图标）/ `ui_`（UI 件）/ `fx_`（迷雾/叠加/演出件）；单位动作件沿批 1 已定口径 `spr_<域>_<名>_<动作>`（如 `spr_cls_warrior_melee_attack`）；字体件 `font_`（10 组 v1.1 新增）。
  - 【高危②已解除·M6 批 3.5a 落地（2026-10-01 拍板「naming 三加严全采纳」）：naming 校验（V-B2-naming）改 **domain 驱动**——数据比对分支优先（`tile_normal` 等数据 6 条按数据身份走、资产前缀撞带解除）→ assets 域资产分支（**ASSET_ID_PREFIXES 前缀合法集**六前缀 bg_/tile_/icon_/ui_/fx_/spr_ + **registry 键反向登记断言**）→ 子资源特判（NAMING_PREFIX_CHECKS 更名 NAMING_SUBRESOURCE_CHECKS、仅余 tend_）；62 件占位已按本口径三同步入册（registry 118 键、naming 274 条）。**注：`font_` 尚不在合法集内**——字体 2 件素材到位登记时须先扩 ASSET_ID_PREFIXES 一行（否则 assets 域条目前缀校验拦截），见 10 组】
- **id 全局小写下划线**（铁律②同源）；**文件名 == 资源 id**。
- **与 data 域逻辑 id 防撞**：data 域已登记裸语义逻辑 id（如 `tile_normal`/`tile_grass` 等地格类型、`etile_*` 探索地格）——美术资产 id 一律带场景/用途中缀（`tile_mine_*`/`tile_village_*`/`tile_battle_*`），不与逻辑 id 撞名。
- **入库路径**：`assets/` 按分组目录（bg/tiles/icons/ui/fx/units），`<资源 id>.png`；由 `tools/sync_asset_registry.gd` 扫描增量登记（M6 方案 §3.2）。批 3.5a 实况注：占位件入库三同步（PNG+registry+naming）由 `tools/gen_asset_placeholders.gd` 承担、首批正式件由 `tools/process_bg_guild_hall.gd` 承担——通用 sync 工具随正式素材批量入库节奏落地。
- **本目录文档侧定位**：规格书放 `DEMO/art_spec/`（文档侧），不入 `data/` 域、不进 DataValidator 计数带（M6 方案 §3.3 已定）；规格书 id 清单即美术盘点源。
