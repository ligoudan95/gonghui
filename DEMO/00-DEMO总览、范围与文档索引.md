## 1. 本 DEMO 要验证什么

本 DEMO 只验证一条因果链是否成立：

> 为了一个调查目标管理队伍 → 用有限资源降低未知 → 在节点地图上选择路线 → 在主战棋中决定优先目标 → 带着多级结果回城 → 看见队伍、支援和世界受到不同影响。

必须让玩家在一小时内理解四件事：

1. 工会筹备会改变远征选择，而不是出发前的纯菜单点击。
2. 大地图的信息层级和路线成本支持推理，关键事实不靠随机硬卡。
3. 战棋是救援、取证、追敌等目标的兑现，不是单纯清场。
4. 特殊 NPC 是有个人问题和代价的外部支援；不做支线也能走基础路线。

本 DEMO 不验证长期经济、完整势力、完整恋爱、次要小队派遣和多章节继承。

## 2. 硬范围

| 模块 | DEMO 冻结范围 | 明确不做 |
|---|---|---|
| 工会据点 | 1 个总览界面/简化场景 | 自由行走建筑群 |
| 普通冒险者 | 4 名可选，固定 3 人出战 | 大规模招募、复杂关系图 |
| 特殊 NPC | 3 名；1 条完整首章支线、2 条首阶段 | 全量个人故事、复杂恋爱演出 |
| 主线 | 旧矿道失踪调查 1 条 | 第二章节、多区域主线 |
| 准备委托 | 2 条固定准备委托 | 随机委托生成器 |
| 区域地图 | 1 张、8 个核心节点 | 第二张地图、程序生成地图 |
| 战棋 | 1 场主战棋 | 多场资源战、完整敌人图鉴、短遭遇（如需加入走变更流程） |
| 结果 | 五类结果（完全成功/代价成功/部分成功/撤退/失败继续）中至少实现 3 种 | 只有胜负二元结算 |
| 资源 | 资金、补给、事实情报、声望、1 个联络位 | 长期生产链、装备词条、季节天气 |
| 存档 | 自动存档 + 1 个手动槽 | 云同步、联网验证 |
| 难度 | 辅助/标准/挑战三档 | 高风险永久死亡模式 |

### 2.1 范围裁剪原则

- **D00-01 [冻结]** 新增系统必须直接服务经营准备、节点探索、战棋目标或特殊 NPC 助力四项卖点之一。
- **D00-02 [冻结]** 新增内容必须在本次游玩中可见、可理解、可测试；否则留到正式版。
- **D00-03 [冻结]** 新增系统必须明确砍掉等规模内容、增加的状态字段、存档影响和测试用例。
- **D00-04 [禁止]** 用“以后再补”掩盖 DEMO 中缺失的失败结算、基础路线、资源账本或存档幂等。

## 3. 时间目标

| 玩家类型 | 目标 | 上限/下限 | 观察重点 |
|---|---:|---:|---|
| 首次游玩 | 60–70 分钟 | 不超过 75 分钟 | 是否看懂筹备和支援代价 |
| 熟悉系统 | 40–55 分钟 | 不低于 35 分钟 | 是否能快速做出路线判断 |
| 失败路线 | 50–70 分钟 | 结算后可继续 | 失败是否有内容而非 game over |

建议分段预算：

| 阶段 | 首次预算 | 熟悉后预算 | 说明 |
|---|---:|---:|---|
| 开场与教程 | 5–8 分钟 | 3–5 分钟 | 第一次展示资金、队伍和目标 |
| 筹备与准备委托 | 10–12 分钟 | 6–9 分钟 | 至少一次明确取舍 |
| 特殊 NPC 接触 | 5–7 分钟 | 3–5 分钟 | 至少看到一项独特助力 |
| 地图探索 | 14–18 分钟 | 10–13 分钟 | 访问 5–7 个节点 |
| 主战棋 | 15–20 分钟 | 10–15 分钟 | 2 个以上竞争目标 |
| 结果与回响 | 8–10 分钟 | 5–8 分钟 | 2 分钟内先显示结果 |

首次分段上限合计恰为 75 分钟、熟悉后为 55 分钟，与总体上下限一致；单段超时应优先压缩结果回响和探索，不删失败结果或基础路线。

查看日志、档案、帮助、可及性设置不消耗时间；世界周期只在周期关闭事务推进，远征内移动和战棋用 `local_tick` 表示。

## 5. 单次体验流程

```text
开场摘要
  -> 查看工会和四名冒险者
  -> 选择主线调查
  -> 执行最多两次准备动作
  -> 认识/推进特殊 NPC
  -> 锁定队伍、补给、难度与联络位
  -> 进入旧矿道区域
  -> 调查节点、选择长路或捷径
  -> 主战棋：救人、取证、追敌/撤离
  -> 结果待结算：接受结果或合法重试
  -> 回城结算
  -> 队伍短回响与 NPC 支援反馈
  -> 下一次行动的钩子
```

D00-05 [冻结] 无论完全成功、部分成功、撤退还是战棋失败，都必须到达回城结算和下一钩子；不得停在失败画面或无反馈战斗结束处。

## 6. DEMO 规则优先级

1. `DEMO/01` 的阶段、存档和结算规则。
2. `DEMO/02` 的具体资源和时间基线。
3. `DEMO/03`–`05` 的内容配置。
4. `DEMO/06` 的变量和验收映射。
5. `zhengshi/` 正式版规则。
6. 历史 DEMO 原文中的建议。

DEMO 可以减少规模，但不能改变以下共享语义：

- `PREPARING -> PREP_LOCKED -> EXPEDITION -> RESULT_PENDING -> SETTLED -> ECHO -> CYCLE_CLOSED`。
- `CYCLE_CLOSED` 后在同一 `demo_run_id` 内可以继续下一周期（回到 `PREPARING`），也可以进入 `DEMO_EPILOGUE`；同一运行最多 3 个周期。
- 一个 `result_id` 只结算一次。
- 战棋重试完整回到 `COMBAT_START`，战前地图助力不回滚。
- 普通读档是同一 `settlement_epoch` 内整包替换，不跨档合并。
- 无 NPC、低资源和失败后仍保留基础路线或恢复路径。

## 7. DEMO 变更控制

变更申请使用以下模板：

```text
变更编号：D-CHANGE-___
变更目标：
属于四项卖点中的哪一项：
新增/删除文件：
新增变量：
是否改变存档或结算：
是否改变资源净收益：
是否改变基础解法：
预计增加时长：
明确砍掉的内容：
新增测试用例：
```

以下变更默认拒绝：

- 增加第九个以上核心节点而不删除同规模节点。
- 增加 NPC 支援但没有无支援路线。
- 增加奖励但没有 claim key、成本或失败结果。
- 增加随机事件但让它成为唯一主线线索。
- 增加恋爱或派遣系统而没有删除现有主战棋/结算测试。

## 8. DEMO 交付门槛

- [ ] 一次完整游玩能从开场到回城结果。
- [ ] 至少三种主线结果可自然到达。
- [ ] 至少一名特殊 NPC 完成“支线—助力—局内—反馈”闭环。
- [ ] 不使用特殊 NPC 仍能完成主线或到达合理部分结果。
- [ ] 节点奖励不可重复领取，回访有状态变化。
- [ ] 资金、补给、支援次数和伤病能在失败后正确结算。
- [ ] 战棋重试不复制奖励、不恢复战前地图代价。
- [ ] 全员受伤/零资源时有恢复入口。
- [ ] 首次游玩中位时长 60–70 分钟，最长不超过 75 分钟。
- [ ] 连续 5 次成功/失败路径没有软锁、重复奖励和结算阻断。

## 9. 明确不在 DEMO 冻结的问题

- 正式版多章节经济曲线。
- 正式版高风险永久死亡。
- 二周目继承信息。
- NPC 全量恋爱演出和所有个人结局。
- 多区域并行任务与次要小队派遣。

这些内容可以保留为后续设计输入，但不能成为本 DEMO 的隐藏前置条件。
